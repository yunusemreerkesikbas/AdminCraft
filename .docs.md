# ItemDialog - Reusable CRUD Dialog Component

## 📋 Overview

Schema-driven dialog component for Create/Edit operations with multi-language tabs (General + TR/EN).

## 🚀 Quick Start

```typescript
import { ItemDialogService } from '@shared/services/item-dialog.service';

export class MyListComponent {
  #dialogService = inject(ItemDialogService);
  #myService = inject(MyService);
  #notification = inject(NotificationService);

  create(): void {
    const options: ItemDialogOptions<MyDto> = {
      mode: 'create',
      titleKey: 'admin.myModule.entityName',
      schema: this.#buildSchema(),
      languages: ['tr', 'en'],
      initial: {
        status: 'DRAFT',
        tr: { title: '', description: '' },
        en: { title: '', description: '' }
      }
    };

    this.#dialogService.open<MyDto>(options)
      .pipe(take(1))
      .subscribe((result) => {
        if (!result) return;
        this.#myService.create(result).pipe(take(1)).subscribe(() => {
          this.#notification.success('admin.messages.createSuccess');
          this.#loadData();
        });
      });
  }

  #buildSchema(): ItemDialogSchema {
    return {
      general: [
        {
          key: 'status',
          type: 'select',
          labelKey: 'admin.fields.status',
          required: true,
          options: [
            { value: 'ACTIVE', labelKey: 'admin.status.active' }
          ]
        }
      ],
      i18n: [
        {
          key: 'title',
          type: 'text',
          labelKey: 'admin.fields.title',
          required: true,
          maxLength: 200
        }
      ]
    };
  }
}
```

## 📝 Field Types

| Type | Usage |
|------|-------|
| `text` | Single-line input |
| `textarea` | Multi-line input |
| `select` | Dropdown with options |
| `number` | Numeric input |
| `checkbox` | Boolean toggle |

## 🎯 API

**ItemDialogOptions:**

```typescript
{
  mode: 'create' | 'edit';
  titleKey: string;              // i18n key
  schema: ItemDialogSchema;
  languages: ['tr', 'en'];
  initial?: Partial<TDto>;
  id?: TId;                      // For edit mode
  modalData?: {
    width?: string;              // Default: '720px'
    disableClose?: boolean;      // Default: true
  }
}
```

**Return Value:**

```typescript
{
  // General fields
  status: 'ACTIVE',
  
  // Language fields
  tr: { title: 'Başlık' },
  en: { title: 'Title' }
}
```

## ✅ Best Practices

- Always use `.pipe(take(1))` to prevent memory leaks
- Provide initial values for all schema fields
- Use strong typing: `open<MyDto, number>(options)`
- Private methods with `#` prefix


```typescript
import { SpaGenericModalComponent, ModalConfig } from '@shared/components/spa-generic-modal';

// Credentials Modal
const config: ModalConfig<AdminUserResponse> = {
    type: 'success',
    variant: 'credentials',
    title: 'Admin User Created',
    icon: 'celebration',
    data: response,
    sections: [
        { type: 'info-box', title: 'Tenant:', content: response.subdomain },
        {
            type: 'copyable-fields',
            fields: [
                { icon: 'email', label: 'Email', value: response.email, type: 'text' },
                { icon: 'key', label: 'Password', value: response.temporaryPassword, type: 'password' },
```

## Subdomain-Based Tenant Authentication (Sprint 17)

**What Changed:** Tenant users login via subdomain resolution (`democompany.localhost`) instead of path-based routing.

**Problem Solved:** Tenant admin login returned 401 because backend queried `platform_management.users` instead of `ac_tenant_{id}.users`. Root cause: no tenant identifier in request.

### Authentication Flow

**Headers Priority:**

| Priority | Header | Use Case |
|----------|--------|----------|
| 2 | `X-Tenant-Subdomain: democompany` | New (recommended) |
| 3 | None | SUPER_ADMIN platform login |

**Special subdomain:** `admin` → Platform admin auth

### Backend: Subdomain Resolution

**Critical Pattern:**

```java
// AuthenticationServiceImpl.java
if (subdomain != null && !subdomain.equals("admin")) {
    Tenant tenant = tenantRepository.findBySubdomain(subdomain);
    validate(tenant.isActive());

    // MUST set context BEFORE UserRepository query
    tenantContext.setTenantId(tenant.getId());
    tenantContext.setTenantDbName(tenant.getDatabaseName());
}

// Now queries correct tenant DB
User user = userRepository.findByEmail(email);
```

**Files Changed:**

- `AuthenticateCommand.java` - Added `subdomain` field
- `AuthController.java` - Reads `@RequestHeader("X-Tenant-Subdomain")`
- `AuthenticationServiceImpl.java` - Tenant resolution logic

### Frontend: Hostname Parsing

**Subdomain Extraction:**

```typescript

// module-provision-dialog.component.ts
pollJobStatus(jobId: string): void {
  interval(2000).pipe(
    switchMap(() => this.service.getJobStatus(jobId)),
    takeWhile(job =>
      job.status === 'pending' || job.status === 'running',
      true  // Emit final value
    )
  ).subscribe(/* handle result */);
}
```
