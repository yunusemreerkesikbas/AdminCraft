## Design Context

### Users
Craftive documentation serves a hybrid audience. The first lane is operators, content teams, and project owners who need short, task-based guidance for daily platform work. The second lane is developers and implementers who need codebase-backed architecture, tenant-safety rules, delivery contracts, and integration notes. The site is a published documentation surface, while the repository `docs/` directory remains the English-only source corpus.

### Brand Personality
Trustworthy, exact, calm. The interface should reduce ambiguity, feel editorial rather than dashboard-like, and present technical depth without visual noise. It should read like a precise internal publication for a serious B2B platform team, not like startup landing-page marketing.

### Aesthetic Direction
Editorial precise. Default to a light, paper-and-ink reading experience with restrained contrast, strong typography, and subtle atmospheric surfaces. Avoid loud gradients, generic SaaS cards, and decorative chrome. The published site supports both English and Turkish, but should make the English-only source model clear.

### Design Principles
1. Separate the two audiences clearly: operator guides and developer documentation should feel connected, but never blended into the same reading lane.
2. Make source-of-truth boundaries explicit: repository source docs are English-only; the Docusaurus publication layer is localized EN/TR.
3. Prefer information architecture, typography, and spacing over decorative effects.
4. Keep the tone concise, codebase-backed, and operationally useful.
5. Treat every page as a reading surface first, a marketing surface second.
