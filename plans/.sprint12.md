# Sprint 12 – DB-per-Tenant with Flyway (Header-based)

## Scope decisions (final)

- Tenant DB creation: single local MySQL instance; app user has CREATE DATABASE; DB name `ac_tenant_{tenantId}` (utf8mb4/utf8mb4_unicode_ci)
- Tenant resolution (local): `X-Tenant-ID` only (fallback model). Subdomain/JWT support designed but disabled
- Platform schema name: `platform_management`
- Eliminate manual SQL scripts; Flyway manages all migrations
- ORM (Hibernate) with `ddl-auto=none`; schema control via Flyway only

## Backend changes

**1. Docker & legacy cleanup**

- Update `docker/mysql/init/01-init-database.sql` → create only `platform_management` DB (utf8mb4/utf8mb4_unicode_ci)
- Remove all tenant tables from init script; they belong to per-tenant DBs
- Delete `backend/src/main/resources/schema-page-builder.sql` (convert to Flyway)
- Delete `backend/src/main/resources/data.sql` (convert to Flyway repeatable)

**2. Flyway configuration**

- Add Flyway dependency to `pom.xml`
- Configure platform Flyway in `application.yml`:
- `spring.jpa.hibernate.ddl-auto=none` (Flyway manages schema)
- `spring.flyway.enabled=true`, `locations=classpath:db/platform`
- Tenant Flyway: programmatic per-tenant DS with dynamic locations `db/tenant/core`, `db/tenant/{moduleCode}`

**3. Platform DB migrations**

- Create `backend/src/main/resources/db/platform/V1__baseline.sql`:
- `tenants(id, subdomain, custom_domain, db_host, db_port, db_name, status, default_language, supported_languages, created_at, updated_at)`
- `modules_catalog(id, code UNIQUE, name, type, version, deps JSON, enabled_by_default)`
- `tenant_modules(id, tenant_id, module_code, status, target_version)`
- `provisioning_jobs(id, tenant_id, type, payload JSON, status, progress, error, created_at, updated_at)`
- Create `backend/src/main/resources/db/platform/R__seed_modules.sql`:
- Insert modules: `core`, `pagebuilder`, `site_settings` with type/version/deps

**4. Tenant DB migrations**

- Create `backend/src/main/resources/db/tenant/core/V1__baseline.sql`:
- `users`, `roles`, `site_settings` tables
- Create `backend/src/main/resources/db/tenant/core/R__seed_roles.sql`:
- Insert TENANT_ADMIN, EDITOR, VIEWER roles
- Convert `schema-page-builder.sql` → `backend/src/main/resources/db/tenant/pagebuilder/V1__baseline.sql`:
- `pages`, `page_i18n`, `page_categories`, `page_category_translations`, `page_sections`, `page_blocks`
- Remove idempotent SET @fk_exists logic; Flyway handles versioning
- Optional: `backend/src/main/resources/db/tenant/pagebuilder/R__seed_sample_pages.sql` for demo data

**5. Multi-tenant runtime**

- `infrastructure/tenant/TenantContext`: ThreadLocal storing `tenantId`, `tenantDbName`
- `infrastructure/tenant/TenantFilter`: Extract `X-Tenant-ID`, load platform tenant row, set/clear context (try/finally)
- `infrastructure/tenant/MultiTenantConnectionProvider`: Hikari DS cache (LRU idle eviction: maxPools=10, maxPerTenant=5, idleEvict=30m)
- `infrastructure/tenant/CurrentTenantIdentifierResolver`: Returns `db_name` from TenantContext
- Configure Hibernate multi-tenancy: `DATABASE` strategy in `application.yml`

**6. Platform data access**

- Configure `PlatformDataSource` bean (separate from tenant DS)
- Create platform JPA entities: `Tenant`, `ModuleCatalog`, `TenantModule`, `ProvisioningJob`
- Repositories: `TenantRepository`, `ModuleCatalogRepository`, `ProvisioningJobRepository`
- Services: `TenantService`, `ProvisioningService`

**7. Provisioning service**

- `createDatabaseIfNotExists(dbName)`: Execute `CREATE DATABASE ac_tenant_{id} CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci`
- Programmatic Flyway migrate: Build tenant DS, configure locations (`core` + selected modules), run migrate
- Minimal seed via repeatable migrations (roles + site settings baseline)
- Job lifecycle: `pending → running → succeeded/failed`; progress: 10% (create DB) → 40% (core) → 80% (modules) → 90% (seed) → 100%
- Error handling: Truncate error messages; log full stacktrace with correlationId

**8. REST APIs (presentation)**

- `POST /api/tenants/{id}/provision` body `{ modules: string[] }` → `{ jobId }` (admin-only, rate-limited)
- `GET /api/provisioning/jobs/{jobId}` → `{ status, progress, error?, startedAt, finishedAt }`
- `GET /api/modules/catalog` → `[ { code, name, type, version, deps[], enabledByDefault } ]`

**9. Observability & security**

- MDC: Add `tenantId`, `tenantDb`, `correlationId` to all log entries
- Global exception handler: Generic messages; localized via `messages_{lang}.properties`
- Rate limiter: Simple in-memory (Guava RateLimiter); 5 provision requests/minute per tenant

## Frontend Admin changes

- Single `provision-dialog` component (dynamic, type-driven):
  - Module provisioning: Fetch `modules_catalog`, grouped by type (core/b2b/b2c); dependency-aware selection; submit to `POST /api/tenants/{id}/provision`
  - Language provisioning: Confirmation dialog with progress tracking
- Submit provisioning request, receive `jobId`
- Poll `GET /api/provisioning/jobs/{jobId}` every 2s; show progress bar & status badge
- Retry button on `failed` status

## Testing

- Testcontainers MySQL: Boot with platform DB; run platform Flyway
- Provision two tenants with different module sets
- Assert isolation: CRUD in tenant A invisible in tenant B
- Idempotency: Re-run same modules → no-op; job succeeds without duplicate DDL errors
