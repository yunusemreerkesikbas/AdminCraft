# Sprint 13 — Page Categories i18n Alignment

## Implementation Summary

### Completed Backend Tasks ✅

#### 1. Domain Layer Refactoring
- **PageCategory Entity**: Migrated from standalone entity to extend `BaseEntity`
  - Removed language-specific fields (name, slug, path, level, status)
  - Now contains only language-agnostic fields: id, uuid, uid, tenantId, parentId, active, styleClasses, sortOrder
  - Inherits createdAt, updatedAt, createdBy, updatedBy from BaseEntity

- **PageCategoryI18n Entity**: Created new i18n entity extending `BaseI18nEntity`
  - Renamed from `PageCategoryTranslation` to `PageCategoryI18n`
  - Table renamed from `page_category_translations` to `page_category_i18n`
  - Fields: id, uuid, uid, tenantId, language, categoryId, url (renamed from slug), title, metaTitle, metaDescription, active
  - Constraints:
    - unique(tenant_id, category_id, language)
    - unique(tenant_id, uid)
    - unique(tenant_id, language, url)

#### 2. Repository Layer
- **PageCategoryRepository**: Updated interface
  - Removed slug/path-based queries
  - Added `findByTenantIdOrderBySortOrderAsc`
  - Simplified to base CRUD operations

- **PageCategoryI18nRepository**: Renamed and updated
  - Renamed from `PageCategoryTranslationRepository`
  - Added URL uniqueness checks
  - Methods for finding by tenant, category, language

#### 3. Application Layer
- **New DTOs Created**:
  - `PageCategoryListResponse`: For list endpoint (no tenantId)
  - `PageCategoryDetailResponse`: For detail endpoint with translations
  - `PageCategoryI18nResponse`: For i18n-specific responses
  - `PageCategoryMetadataResponse`: Contains translationCount, publishedTranslationCount
  - `UpsertPageCategoryI18nRequest`: For creating/updating i18n content

- **Request DTOs Updated**:
  - `CreatePageCategoryRequest`: Removed tenantId, name, slug; added uid, active, styleClasses
  - `UpdatePageCategoryRequest`: Simplified to only updateable base fields

- **Service Layer Rewritten**:
  - `PageCategoryService`: New interface with i18n-aware methods
  - `PageCategoryServiceImpl`: Complete rewrite
    - `create()`: Creates base category with tenant from context
    - `update()`: Updates base fields only
    - `getDetailById()`: Returns base + translations when `include=translations`
    - `listByTenant()`: Returns list with translation availability map
    - `upsertI18n()`: Creates or updates language-specific content
    - `getI18n()`: Retrieves specific language content

#### 4. Presentation Layer
- **PageCategoryController**: Completely rewritten
  - `POST /page-categories`: Create base category
  - `PUT /page-categories/{id}`: Update base category
  - `GET /page-categories`: List all categories (language-agnostic)
  - `GET /page-categories/{id}?include=translations`: Get detail with optional translations
  - `DELETE /page-categories/{id}`: Delete category
  - `PUT /page-categories/{id}/i18n/{language}`: Upsert i18n content
  - `GET /page-categories/{id}/i18n/{language}`: Get i18n content
  - All responses wrapped in `ApiResponse`
  - No tenantId in responses (handled via SecurityHelper)

#### 5. Database Migration
- **003_page_categories_i18n_migration.sql**: Created comprehensive migration
  - Add BaseEntity fields to page_categories
  - Create page_category_i18n table with proper constraints
  - Migrate existing data to i18n table (assumes TR language)
  - Backfill uuid and uid for existing categories
  - Remove old language-specific columns from base table
  - Drop obsolete indexes and constraints

#### 6. i18n Messages
- **messages_tr.properties**: Added Turkish messages
  - Category CRUD success/error messages
  - i18n-specific success/error messages
  - Technical error messages with correlation IDs

- **messages_en.properties**: Added English messages
  - Matching keys with English translations

### Key Decisions Implemented

1. **No tenantId in Responses**: Tenant handled via `SecurityHelper.getCurrentUserTenantId()`
2. **slug → url**: Renamed in i18n layer for clarity
3. **categoryId → parentId**: Consistent naming in responses
4. **No /tree or /reorder endpoints**: Simplified; use sortOrder in base update
5. **include parameter**: `?include=translations` to load translations in detail endpoint
6. **Metadata**: Returns translationCount and publishedTranslationCount

### Security & Multi-Tenancy

1. **TenantContext**: All service methods receive tenantId from `SecurityHelper`
2. **Validation**: Parent category belongs to same tenant
3. **URL Uniqueness**: Enforced per (tenant, language)
4. **No Tenant Leakage**: tenantId not exposed in responses
5. **Audit Logging**: All CRUD operations logged with correlation IDs
