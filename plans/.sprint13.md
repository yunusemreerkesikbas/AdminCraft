# Sprint 13 — Page Categories i18n Alignment

## Implementation Summary

### Completed Backend Tasks ✅

#### 1. Domain Layer Refactoring
- **PageCategory Entity**: Migrated from standalone entity to extend `BaseEntity`
  - Removed language-specific fields (name, slug, path, level, status)
  - Now contains only language-agnostic fields: id, uuid, uid, tenantId, parentId, active, styleClasses, sortOrder
  - Inherits createdAt, updatedAt, createdBy, updatedBy from BaseEntity

- **PageCategoryI18n Entity**: Created new i18n entity extending `BaseI18nEntity`
  - Renamed from `PageCategoryTranslation` to `PageCategoryI18n`
  - Table renamed from `page_category_translations` to `page_category_i18n`
  - Fields: id, uuid, uid, tenantId, language, category (ManyToOne), url (renamed from slug), title, metaTitle, metaDescription, active
  - **JPA Relationship**: Added `@ManyToOne(fetch = FetchType.LAZY)` to category field for proper entity relationship management
  - Constraints:
    - unique(tenant_id, category_id, language)
    - unique(tenant_id, uid)
    - unique(tenant_id, language, url)

#### 2. Repository Layer
- **PageCategoryRepository**: Updated interface
  - Removed slug/path-based queries
  - Added `findByTenantIdOrderBySortOrderAsc`
  - Added `existsByTenantIdAndUid` for UID uniqueness validation
  - Added `delete(PageCategory)` method for secure entity deletion
  - Simplified to base CRUD operations

- **PageCategoryI18nRepository**: Renamed and updated
  - Renamed from `PageCategoryTranslationRepository`
  - Added URL uniqueness checks
  - Added `findByTenantIdAndCategoryIdIn` for batch loading (N+1 query optimization)
  - Methods for finding by tenant, category, language
  - Updated method names to use `category_Id` notation for JPA relationship queries

#### 3. Application Layer
- **Command Objects** (Clean Architecture Pattern):
  - `CreatePageCategoryCommand`: Command for creating base category
  - `UpdatePageCategoryCommand`: Command for updating base category
  - `UpsertPageCategoryI18nCommand`: Command for creating/updating i18n content

- **Query Objects** (Clean Architecture Pattern):
  - `PageCategoryDetailQuery`: Query with includeTranslations flag

- **Response DTOs Created**:
  - `PageCategoryListResponse`: For list endpoint (no tenantId)
  - `PageCategoryDetailResponse`: For detail endpoint with translations
  - `PageCategoryI18nResponse`: For i18n-specific responses
  - `PageCategoryMetadataResponse`: Contains translationCount, publishedTranslationCount

- **Request DTOs Updated** (Presentation Layer):
  - `CreatePageCategoryRequest`: Removed tenantId, name, slug; added uid, active, styleClasses
  - `UpdatePageCategoryRequest`: Simplified to only updateable base fields
  - `UpsertPageCategoryI18nRequest`: For creating/updating i18n content

- **Service Layer Rewritten** (Application Layer):
  - `PageCategoryService`: New interface using Command/Query objects instead of Presentation DTOs
  - `PageCategoryServiceImpl`: Complete rewrite following Clean Architecture
    - `create(CreatePageCategoryCommand)`: Creates base category with UID uniqueness validation
    - `update(UpdatePageCategoryCommand)`: Updates base fields only
    - `getDetailById(PageCategoryDetailQuery)`: Returns base + translations when `include=translations`
    - `listByTenant()`: Returns list with translation availability map (optimized with batch loading)
    - `upsertI18n(UpsertPageCategoryI18nCommand)`: Creates or updates language-specific content
    - `getI18n()`: Retrieves specific language content
    - `delete()`: Uses entity deletion for tenant security

#### 4. Presentation Layer
- **PageCategoryController**: Completely rewritten with Clean Architecture compliance
  - Maps Request DTOs to Command/Query objects before calling service
  - `POST /page-categories`: Create base category (maps CreatePageCategoryRequest → CreatePageCategoryCommand)
  - `PUT /page-categories/{id}`: Update base category (maps UpdatePageCategoryRequest → UpdatePageCategoryCommand)
  - `GET /page-categories`: List all categories (language-agnostic)
  - `GET /page-categories/{id}?include=translations`: Get detail (creates PageCategoryDetailQuery)
  - `DELETE /page-categories/{id}`: Delete category
  - `PUT /page-categories/{id}/i18n/{language}`: Upsert i18n content (maps UpsertPageCategoryI18nRequest → UpsertPageCategoryI18nCommand)
  - `GET /page-categories/{id}/i18n/{language}`: Get i18n content
  - All responses wrapped in `ApiResponse`
  - No tenantId in responses (handled via SecurityHelper)

#### 5. Database Migration
- **003_page_categories_i18n_migration.sql**: Created comprehensive migration with safety checks
  - Add BaseEntity fields to page_categories with `IF NOT EXISTS` checks
  - Create page_category_i18n table with proper constraints
  - Migrate existing data to i18n table (assumes TR language)
  - Backfill uuid and uid for existing categories using sequential IDs (`CONCAT('catitem_', LPAD(id, 8, '0'))`)
  - Drop existing constraints before re-adding to prevent duplication errors
  - Remove old language-specific columns from base table
  - Drop obsolete indexes and constraints
  - **Security Fix**: Changed from RAND() to sequential ID-based UID generation to prevent collisions

#### 6. i18n Messages
- **messages_tr.properties**: Added Turkish messages
  - Category CRUD success/error messages
  - i18n-specific success/error messages
  - Technical error messages with correlation IDs

- **messages_en.properties**: Added English messages
  - Matching keys with English translations

### Key Decisions Implemented

1. **Clean Architecture Compliance**: Application layer uses Command/Query pattern instead of depending on Presentation DTOs
2. **No tenantId in Responses**: Tenant handled via `SecurityHelper.getCurrentUserTenantId()`
3. **slug → url**: Renamed in i18n layer for clarity
4. **categoryId → parentId**: Consistent naming in responses
5. **No /tree or /reorder endpoints**: Simplified; use sortOrder in base update
6. **include parameter**: `?include=translations` to load translations in detail endpoint
7. **Metadata**: Returns translationCount and publishedTranslationCount
8. **JPA Relationship**: PageCategoryI18n uses @ManyToOne relationship instead of just categoryId
9. **Performance Optimization**: Batch loading with `findByTenantIdAndCategoryIdIn` prevents N+1 queries
10. **Security Enhancements**:
    - UID uniqueness validation before creation
    - Entity-based deletion instead of deleteById for tenant safety
    - Sequential UID generation in migration instead of random

### Security & Multi-Tenancy

1. **TenantContext**: All service methods receive tenantId from `SecurityHelper`
2. **Validation**: Parent category belongs to same tenant
3. **URL Uniqueness**: Enforced per (tenant, language)
4. **UID Uniqueness**: Validated before category creation to prevent duplicates
5. **No Tenant Leakage**: tenantId not exposed in responses
6. **Secure Deletion**: Uses `delete(entity)` instead of `deleteById(id)` to prevent cross-tenant deletion
7. **Audit Logging**: All CRUD operations logged with correlation IDs
