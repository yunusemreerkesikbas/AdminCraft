# SUPER_ADMIN Tenant-Agnostic Login & Impersonation

## Summary

## Implementation Status: ✅ COMPLETED

### Backend Changes

**1) Platform DB Migration** ✅

- `db/platform/V2__platform_admin_users.sql` created
- Table: `platform_admin_users` (id, email UNIQUE, password_hash, full_name, is_active, created_at, updated_at)

**2) Platform Admin Entity/Repository** ✅

- `PlatformAdminUser` entity: `@Table(schema="platform_management")`
- `PlatformAdminUserRepository` with platform `@Qualifier`

**3) Clean Architecture Refactor** ✅

- Created `AuthenticateCommand(email, password, tenantId, preferredLanguageCode)`
- `AuthenticationService.authenticate(AuthenticateCommand)` (no servlet coupling)
- Service branches by `command.tenantId()`:
  - `null` → platform admin via `PlatformAdminUserRepository`
  - non-null → tenant user via `UserRepository`

**4) SUPER_ADMIN Token Lifecycle** ✅

- `refreshToken()`: Detects `SUPER_ADMIN` + `tenantId=null` → uses platform repo
- `logout()`: Handles platform admin consistently
- JWT mapping: `role: "SUPER_ADMIN"` → authority `ROLE_SUPER_ADMIN`

**5) Security Filter Order** ✅

- `JwtAuthenticationFilter` → `TenantFilter`
- `TenantFilter.doFilterInternal()`:
  - Whitelisted paths → pass
  - `ROLE_SUPER_ADMIN` + no header → pass (no context)
  - `ROLE_SUPER_ADMIN` + header → impersonation (set context)
  - Others → require tenant header

**6) Configuration Fixes** ✅

- `application.yml`: `spring.datasource.platform.url` + `jdbc-url` (Hikari compatibility)
- Testcontainers `DynamicPropertySource`: binds both keys

**7) Flyway Migration Issues Resolved** ✅

- **Version conflict**: Renamed `db/tenant/pagebuilder/V1__baseline.sql` → `V2__baseline.sql`
- **CHECK constraint**: Removed `chk_category_no_self_parent` (AUTO_INCREMENT column restriction)
- **Seed data**: Cleared `R__seed_sample_pages.sql` (user dependency issue)

**8) Async Provisioning Fix** ✅

- `ProvisioningServiceImpl`: Async call deferred to `afterCommit()` via `TransactionSynchronization`
- Prevents race condition where job not yet persisted before async execution

**9) Messages (i18n)** ✅

- `messages_tr.properties` / `messages_en.properties`: platform admin login keys added
- Login response language from `Accept-Language` header (no hardcoded "TR")
