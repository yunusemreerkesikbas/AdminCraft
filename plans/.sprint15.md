# SUPER_ADMIN Tenant-Agnostic Login & Impersonation

## Summary

Add platform-level admin users in platform DB and allow `SUPER_ADMIN` to login without `X-Tenant-ID`. JWT will omit `tenantId` for platform admins. `TenantFilter` will permit no-tenant requests for `SUPER_ADMIN`, and set tenant context only when `X-Tenant-ID` is present (impersonation). Frontend interceptor will not force `X-Tenant-ID` when no tenant is selected.

## Backend Changes

1) Platform DB Migration

- Add: `backend/src/main/resources/db/platform/V2__platform_admin_users.sql`
- Table `platform_admin_users` (id, email UNIQUE, password_hash, full_name, is_active, created_at, updated_at)
- Optional seed: `backend/src/main/resources/db/platform/R__seed_platform_admin.sql` (disabled by default; use secure bootstrap only)

2) Platform Admin Entity/Repository (Platform DS)

- Add entity `PlatformAdminUser` in `backend/src/main/java/com/backend/infrastructure/persistence/platform/entity/`
- Annotate with `@Table(schema = "platform_management", name = "platform_admin_users")`
- Add repository `PlatformAdminUserRepository` in `.../platform/repository/` using platform `EntityManager`/DS

3) Authentication Flow Update

- Update `AuthenticationServiceImpl.authenticate(LoginRequest)`
- If `X-Tenant-ID` header is missing: lookup `PlatformAdminUser` by email → verify password → issue access/refresh tokens with role `SUPER_ADMIN` and `tenantId = null`
- Else: keep existing tenant user login flow
- Preserve `LoginResponse` shape; `tenantId` will be `null` for platform admins

4) Security Filter Order

- In `SecurityConfig` `SecurityFilterChain`, ensure ordering: `JwtAuthenticationFilter` runs before `TenantFilter`, and register `TenantFilter` with `addFilterAfter(tenantFilter, JwtAuthenticationFilter.class)`

5) TenantFilter Adjustment (impersonation)

- If path is whitelisted → pass (no change)
- Else:
- Read `SecurityContext` role (populated by JWT filter)
- If role == `ROLE_SUPER_ADMIN` and no `X-Tenant-ID`: allow through without setting `TenantContext`
- If `X-Tenant-ID` present: validate ACTIVE tenant and set `TenantContext` (impersonation)
- Retain try/finally to clear context and MDC

6) Messages (i18n)

- Add/adjust messages in `backend/src/main/resources/i18n/messages_tr.properties` and `messages_en.properties` for platform admin login outcome

## Frontend Changes

7) Tenant Header Interceptor

- Update `storefront/src/app/core/tenant/tenant.interceptor.ts`
- Only add `X-Tenant-ID` if a tenant is selected in client state
- SUPER_ADMIN with no selected tenant → no header (platform endpoints keep working)

## Tests

8) Unit/Integration Tests

- Unit: TenantFilter
- SUPER_ADMIN without header → let pass, no context set
- SUPER_ADMIN with header → context set to that tenant
- Integration: AuthController + AuthenticationService
- Platform admin login without `X-Tenant-ID` succeeds and returns JWT without `tenantId`
- Normal tenant user login unchanged
