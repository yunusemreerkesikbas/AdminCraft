## Backend Guide (Sprint 18)

### Endpoints (Tenants)

- POST `/tenants` (SUPER_ADMIN): returns `TenantDetailResponse`
- GET `/tenants` (SUPER_ADMIN): returns `TenantListResponse[]`
- GET `/tenants/{id}` (SUPER_ADMIN): returns `TenantDetailResponse`
- PUT `/tenants/{id}` (SUPER_ADMIN): returns `TenantDetailResponse`
- DELETE `/tenants/{id}` (SUPER_ADMIN)
- GET `/tenants/{id}/admin` (SUPER_ADMIN): returns `TenantAdminInfoResponse`

### DTOs

- `TenantListResponse`: id, subdomain, companyName, status(+display), defaultLanguage(+display), supportedLanguages, provisioningStatus(idle|provisioning|failed), provisionedModulesCount, createdAt, activatedAt, customDomain, sslEnabled
- `TenantDetailResponse`: List fields + databaseName, timezone, currency, storageUsedMb, fullDomain, updatedAt, lastBackupAt, notes
- `TenantAdminInfoResponse`: adminEmail, adminName, phone

### Status fields

- `provisioningStatus` comes from enum `ProvisioningStatus` (IDLE|PROVISIONING|FAILED), exposed as lowercase string.

### Security

- All tenant endpoints require `SUPER_ADMIN`.
- PII only via `/tenants/{id}/admin`.

### Clean Architecture

- Controllers map Request DTO → Command (`CreateTenantCommand`, `UpdateTenantCommand`).
- Application services/use cases consume Commands.

### Error Handling

- Central `@ControllerAdvice`; generic i18n messages returned.

### Frontend Notes

- Rely on `provisioningStatus`: `idle | provisioning | failed`.
- Use `/tenants/{id}/admin` for admin PII; not in list/detail.

### ⚡ Optimization: Stop Polling After Job Completion

**Problem**: Module provision dialog kept polling `/api/provisioning/jobs/{id}` even after job succeeded/failed, until modal closed (5+ unnecessary requests)

**Solution**: Use RxJS `takeWhile` to stop polling when job completes

**File Changed (1):**

- `storefront/.../module-provision-dialog/module-provision-dialog.component.ts`
  - Import: `takeWhile` from `rxjs`
  - Added conditional polling: continue while `status === 'pending' || 'running'`
  - Stops automatically on `succeeded`/`failed`

**Result**: ✅ Polling stops immediately after job completion, saves network bandwidth
