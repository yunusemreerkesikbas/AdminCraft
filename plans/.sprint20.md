# Sprint 20: On-Demand Tenant Admin User Generation

## 1. Overview

**Problem:** Tenant provisioning is unreliable, often failing at 80% due to an incomplete `users` table migration. The process is also slowed down by creating an admin user during initial setup.

**Solution:** Decouple admin user creation from the main tenant provisioning workflow. A super admin will now generate the tenant's first admin user on-demand *after* the tenant is active. This simplifies provisioning and fixes the critical migration bug.

---

## 2. Architecture & Key Decisions

- **Decoupled Flow:** Tenant creation and admin generation are now two separate processes.
- **`has_admin_user` Flag:** A `boolean` flag will be added to the platform's `tenants` table. This provides an efficient way for the frontend to know whether to display the "Generate Admin" button without querying each tenant's database.
- **Standardized Email:** The admin email will be automatically generated as `admin@{subdomain}.com`.
- **One-Time Credentials:** The generated temporary password will be displayed **only once** in a modal. It will not be stored or be retrievable.
- **Secure Password Generation:** A new `PasswordGeneratorService` will create a 12-character password with uppercase, lowercase, digit, and special characters.

---

## 3. Backend Implementation

1.  **Platform DB Migration (`V10__...`):**
    -   In `tenants` table, add `has_admin_user BOOLEAN DEFAULT FALSE`.
    -   Modify `admin_email` and `admin_name` columns to be `NULL`.

2.  **Tenant DB Migration (`core/V2__...`):**
    -   In `users` table, add missing columns to align with the `User` entity (`avatar_url`, `first_name`, `last_name`, `department`, `two_factor_enabled`, etc.). This is the fix for the provisioning crash.

3.  **Refactor Provisioning Flow:**
    -   **`CreateTenantRequest.java`:** Remove `adminEmail` and `adminName` fields.
    -   **`AsyncProvisioningExecutor.java`:** Remove the `createAdminUser()` step from the provisioning process. Re-balance progress percentages.

4.  **New Admin Generation Endpoint:**
    -   **Controller:** In `TenantController.java`, add `POST /{id}/generate-admin`.
    -   **Logic:**
        -   Verify the tenant exists, is `ACTIVE`, and `has_admin_user` is `false`.
        -   Set the `TenantContext` to switch to the correct tenant database.
        -   Use `PasswordGeneratorService` to create a temporary password.
        -   Create a new `User` entity, set its role to `TENANT_ADMIN`, and save it to the tenant's `users` table.
        -   Update the `has_admin_user` flag to `true` on the `Tenant` entity in the platform DB.
        -   Return an `AdminUserResponse` DTO containing the `email`, `temporaryPassword`, and `loginUrl`.

---

## 4. Frontend Implementation

1.  **Types & Services:**
    -   **`tenants.types.ts`:** Add `hasAdminUser: boolean` to the `Tenant` interface. Define the `AdminUserResponse` type.
    -   **`tenant.service.ts`:** Add the `generateAdminUser(tenantId)` method to call the new API endpoint.

2.  **Tenant List Component (`tenants-list.component.html/.ts`):**
    -   **UI:**
        -   Add a status badge (e.g., "Admin Created" / "No Admin") based on the `tenant.hasAdminUser` flag.
        -   Show the "Generate Admin User" button using `*ngIf="!tenant.hasAdminUser && tenant.status === 'ACTIVE'"`.
        -   Show a disabled button with a checkmark if `tenant.hasAdminUser` is `true`.
    -   **Logic:** The `generateAdminUser()` method will call the service and, on success, open the credentials modal.

3.  **New: Admin Credentials Modal (Generic Modal Implementation):**
    -   Uses the new `SpaGenericModalComponent` - a reusable, type-safe modal system.
    -   **Architecture:** Hybrid approach (type + variant)
        -   `type: 'success'` - Sets color scheme (green/accent)
        -   `variant: 'credentials'` - Defines structure/layout
    -   **Configuration:** Opened with `disableClose: true` to prevent closing on backdrop click or ESC.
    -   **Features:**
        -   Displays email, temporary password, and login URL.
        -   Includes "Copy to Clipboard" functionality for each piece of information.
        -   Shows a strong warning that the password is a one-time view.
    -   **Action:** A single "Close" button to dismiss the dialog.

## 4.1 Generic Modal Component Refactoring

**Purpose:** Create a reusable modal component for credentials, alerts, and confirmations across the application.

**Approach - Hybrid System:**

- **Type** (`success` | `error` | `warning` | `info`): Determines color scheme and emotional tone
- **Variant** (`default` | `credentials` | `confirmation`): Determines structure and content layout
- **Sections**: Modular content blocks (info-box, copyable-fields, alert-box, custom)

**Migration:**

- `admin-credentials-modal` → `spa-generic-modal` with `type: 'success'` and `variant: 'credentials'`

**Location:** `storefront/src/app/shared/components/spa-generic-modal/`

**Benefits:**

- ✅ Reusable across different contexts
- ✅ Type-safe with generics `<T>`
- ✅ Consistent UI/UX patterns
- ✅ Easy to extend with new types/variants
- ✅ Reduced code duplication
