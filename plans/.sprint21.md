# Sprint 21: Role-Based Access Control & Module Loading

## 🎯 Goals

1. Fix TENANT_ADMIN module loading - auto-load after login
2. Implement role separation - SUPER_ADMIN = platform only
3. Add role-based navigation filtering
4. Secure tenant endpoints - block SUPER_ADMIN access
5. Create route guards

---

## 🔍 Current Issues

### 🚨 Critical Security Issues

1. **Authorization Bypass**: SUPER_ADMIN can access ALL tenant endpoints (7 controllers)
2. **Missing Endpoint**: TENANT_ADMIN cannot fetch their own modules
3. **No Role Filtering**: Navigation shows wrong items for both roles
4. **Module Loading**: TENANT_ADMIN login doesn't trigger module loading

---

|---------|-------------|--------------|

| Platform DB | ✅ | ❌ |
| Tenant DB | ❌ | ✅ |
| Pages/Media/Settings | ❌ | ✅ (module-based) |

**Navigation:**

- **SUPER_ADMIN**: Dashboard, Tenant Yönetimi
- **TENANT_ADMIN**: Dashboard, Pages, Media, Settings (based on enabled modules)

## 📋 Implementation Tasks

### Phase 1: Backend Security (CRITICAL - 2h)

#### 1.1 Restrict Controllers to TENANT_ADMIN

Change `@PreAuthorize` from `hasAnyRole('TENANT_ADMIN', 'SUPER_ADMIN')` to `hasRole('TENANT_ADMIN')`:

- [ ] **PageController.java** (line 35)
- [ ] **MediaController.java** (line 31)
- [ ] **SiteController.java** (line 28)
- [ ] **UserController.java** (line 31)
- [ ] **SiteSettingsController.java** (lines 34, 47)
- [ ] **PageCategoryController.java** (line 41)
- [ ] **TenantLanguageController.java** (line 31)

#### 1.2 Add New Endpoint for TENANT_ADMIN

- [ ] **TenantController.java**: Add `GET /api/tenants/current/modules`
  - Role: `@PreAuthorize("hasRole('TENANT_ADMIN')")`
  - Validate: user's tenantId matches X-Tenant-ID header
  - Return: enabled modules only

---

### Phase 2: Frontend User Service (30min)

#### 2.1 Add Synchronous Getter

- [ ] **user.service.ts**: Add `private _currentUser: User | null = null`
- [ ] Add getter: `get user(): User | null { return this._currentUser; }`
- [ ] Update setter to cache: `set user(value) { this._currentUser = value; this._user.next(value); }`

---

### Phase 3: Frontend Navigation Filtering (2h)

#### 3.1 Extend Navigation Types

- [ ] **navigation.types.ts**: Add properties:
  - `requiredRole?: string` - Only show to this role
  - `excludedRoles?: string[]` - Hide from these roles

#### 3.2 Update Navigation Data

- [ ] **navigation/data.ts**: Add role restrictions:
  - "Tenant Yönetimi" → `requiredRole: 'SUPER_ADMIN'`
  - All tenant modules → `excludedRoles: ['SUPER_ADMIN']`

#### 3.3 Update Filtering Logic

- [ ] **navigation/api.ts**:
  - Inject `UserService`
  - Rename method to `filterNavigationByModulesAndRoles()`
  - Add role checks before module checks:
    - If `requiredRole` set and doesn't match → hide
    - If user role in `excludedRoles` → hide
    - Then apply existing module filtering

---

### Phase 4: Frontend Module Loading (2h)

#### 4.1 Add TenantContext Initialization

- [ ] **tenant-context.service.ts**:
  - Inject `UserService`
  - Add `initializeTenantContext(user: User)`:
    - SUPER_ADMIN: call `restoreTenantSelection()`, don't load modules
    - TENANT_ADMIN: call `loadCurrentUserTenantModules(user.tenantId)`
  - Add `loadCurrentUserTenantModules(tenantId)`:
    - Call `/api/tenants/current/modules`
    - Filter enabled modules
    - Update `_tenantModules$`
    - Reload navigation
  - Update `selectTenant()`:
    - Check user role
    - SUPER_ADMIN: set tenant but don't load modules
    - TENANT_ADMIN: existing behavior

#### 4.2 Trigger on Login

- [ ] **auth.service.ts**:
  - Inject `TenantContextService`
  - In `signIn()` after setting user:
    - Call `tenantContext.initializeTenantContext(user)`
    - Chain with `pipe(map(() => response.data))`

---

### Phase 5: Frontend Route Guards (1.5h)

#### 5.1 Create Role Guard

- [ ] **NEW FILE: role.guard.ts**:
  - Create `roleGuard(allowedRoles: string[]): CanActivateFn`
  - Check user role in `user$` observable
  - If not allowed: show toast, redirect based on role
  - Export convenience guards: `tenantAdminGuard`, `superAdminGuard`

#### 5.2 Apply Guards to Routes

- [ ] **app.routes.ts**:
  - `/tenants` → add `canActivate: [superAdminGuard]`
  - `/media`, `/users`, `/sites`, `/pages`, `/settings` → add `canActivate: [tenantAdminGuard]`

---

### Phase 6: Frontend Interceptor (Optional - 30min)
