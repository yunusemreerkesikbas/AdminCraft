# Sprint 23: Module Management Simplification

## Goal

Simplify module architecture, remove page_categories as standalone module, establish manual synchronization workflow.

## Changes

### Module Architecture

**Final module list:** 4 modules

- `core` (required) → users, roles, sites
- `pagebuilder` → pages + page_categories
- `site_settings` → global/i18n config
- `media` → media files with i18n

**Removed:**

- page_categories (as separate module)
- b2c_* modules (future expansion removed)
- b2b_* modules (future expansion removed)
- content module (not implemented)

### page_categories Decision

- **Not shown** in provision dialog
- **Part of** pagebuilder module (mandatory)
- Tables: `db/tenant/pagebuilder/V3__baseline.sql`
- Navigation: Shows when pagebuilder is enabled

### Approach

- **No code generation** (manual synchronization)
- **Single source:** R__seed_modules.sql (platform DB)
- **ModuleCode enum:** Minimal (code only)

## Manual Synchronization Process

When adding new module, update in order:

1. R__seed_modules.sql → INSERT
2. ModuleCode.java → Enum entry
3. NAVIGATION_MODULES.ts → Constant
4. db/tenant/{module}/V*.sql → Migration
