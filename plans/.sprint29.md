# Sprint 29: Generic Reorder System

## 🎯 Goal

Create a standardized, reusable, and "premium" drag-and-drop reordering system for the AdminCraft application. This system will be implemented as a generic Angular component and a backend DTO pattern, to be used across all modules requiring list reordering (e.g., Template Slots, Page Slots, CMS Components).

---

## 📋 Requirements

### Frontend (`spa-reorder-list`)

- **Generic Component**: Must accept any list of items (`T[]`).
- **Flexible Rendering**: Must use `ng-template` or content projection to allow consumers to define how each item looks.
- **Drag-and-Drop**: Encapsulate all `CdkDragDrop` logic (moveItemInArray, etc.).
- **Events**: Emit an `itemsChange` event with the reordered list.
- **Premium UX**: Include polished visuals for drag handles, placeholders, previews, and animations.

### Backend (`ReorderRequest`)

- **Generic DTO**: A single `ReorderRequest<T>` class (or record) to handle reordering payloads.
- **Standardized Endpoint**: Establish a pattern for reorder endpoints (e.g., `PUT /{id}/reorder`).

## 🚀 Acceptance Criteria

1. **Reusability**: The component can be dropped into another module without copying any TS logic.
2. **Persistence**: Reordering emits the correct new order, which can be sent to the backend.
3. **Visuals**: Dragging feels smooth, with clear visual feedback (lifting active item, placeholder for target).
