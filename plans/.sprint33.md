# Sprint 33 - Tenant Migration Sync Feature

## Problem

Existing tenants don't receive new Flyway migrations added after initial provisioning, causing missing tables like `navigation_nodes`.

## Solution

Add manual "Sync Migrations" button to apply missing migrations to existing tenant databases.

## Design Decisions

1. **Flyway handles idempotency** - Only missing migrations are applied
2. **Separate job type** - `sync-migrations` for tracking/logging
3. **Installed modules only** - Sync only runs for already-provisioned modules
4. **Rate limited** - Uses existing rate limiter (5 req/min)
5. **TenantStartupMigrator** - Auto-sync on startup already exists
6. **Configurable auto-sync** - Disable in dev with `app.tenant.auto-sync-on-startup=false`

---

## Configuration

```yaml
# Disable auto-sync on startup (for dev/test)
app:
  tenant:
    auto-sync-on-startup: false
```

Or via command line: `-Dapp.tenant.auto-sync-on-startup=false`
