## 1. Backend Implementation (Completed)

> **Status**: ✅ Deployed & Verified (as of 2026-01-01)

### 1.1 Architecture (Database-per-Tenant)

- **Physical Isolation**: No `tenant_id` columns. Separate DB schemes per tenant.
- **Migration**: Flyway `V20__media_baseline.sql` implemented full DAM schema.

### 1.2 Core Entities

| Entity             | Purpose            | Key Features                                                       |
| :----------------- | :----------------- | :----------------------------------------------------------------- |
| **Media**          | Base file record   | `uuid`, `mimeType`, `storageProvider` (LOCAL), `fileSize`          |
| **MediaI18n**      | Localized metadata | `altText`, `title`, `description` (per language)                   |
| **MediaFolder**    | Organization       | Hierarchical tree, `path`, `depth`, Safe Delete/Move               |
| **MediaContainer** | variants Grouping  | SAP pattern: Master Media + Generated Formats (Thumb, Small, etc.) |

### 1.3 Key Services

- **MediaStorageService**: Async I/O, `uploads/{subdomain}/media/` path structure (Refactored from tenantId), Magic Bytes validation.
- **MediaProcessingService**: Background format generation (Thumbnailator).
- **TenantFilter**: Robust tenant resolution via `X-Tenant-ID`, `X-Forwarded-Host`, `Referer`, or `Origin` (supports Angular Proxy).
- **Controllers**:
  - `MediaController`: Secure (TENANT_ADMIN) APIs + **Public** file download (`/api/media/files/**`) with `permitAll()`.
  - `CmsMediaDeliveryController`: **Public** read-only access for CMS, Rate-limited.

### 1.4 API Endpoints (Core)

```http
GET    /api/media                  # List (paginated)
POST   /api/media/upload           # Upload single file
POST   /api/media/composite        # Atomic Upload + Metadata + i18n
GET    /api/media/folders          # Folder Tree
GET    /api/media/containers/{id}  # Get variants
GET    /api/cms/media/{uid}        # Public CMS Access
```

## 2. Frontend Implementation (Completed)

> **Status**: ✅ Implemented (Angular 19 + Signals)

### 2.1 Architecture

- **Location**: `storefront/src/app/modules/admin/custom/media/`
- **Pattern**: `CrudHttpService` + `CrudStore` (Signals).
- **State Management**: Fully reactive signals for `items`, `folders`, `loading`, `filters`.

### 2.2 Implemented Components

#### Core Components

1. **MediaListComponent** (`media-list/`)

   - Split view layout: **Folder Tree** (Sidebar) + **Media Grid** (Main).
   - Extends `BaseCrudListComponent<Media>`.
   - Features: Search, Type Filter, Server-side Pagination.

2. **MediaFolderTreeComponent** (`media-folder-tree/`)

   - Recursive tree structure.
   - Signal-based expansion/selection state.
   - Context detection for creating/editing folders.

3. **MediaUploadDialogComponent** (`media-upload-dialog/`)

   - **Composite Upload**: Sends file + metadata + i18n in one request.
   - **Dynamic Form**: Generates fields based on Tenant's supported languages.
   - Drag & Drop support with progress tracking.

4. **MediaDetailDialogComponent** (`media-detail-dialog/`)
   - **Dynamic Tabs**: Automatic "General" tab + Tabs for each supported language.
   - **Preview**: Displays image/video/audio with `publicUrl`.
   - **Editing**: Updates metadata and i18n translations.

### 2.3 Key Refactoring Achievements

- **Business Logic**: Removed frontend utility methods (`getMediaType`), switched to using Backend DTO fields (`fileType`, `fileSizeFormatted`).
- **Dynamic i18n**: All dialogs now adapt to the tenant's languages (no hardcoded "TR/EN").
- **State Management**: Migrated from `BehaviorSubject` to `Signals` (`MediaStore`).
- **Confirmation**: Integrated `TranslocoService` for localized confirmation dialogs.
