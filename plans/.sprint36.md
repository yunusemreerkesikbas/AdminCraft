## 1. SAP Hybris Media Architecture Analysis

### 1.1 Core Data Model

| Model                   | Purpose            | Key Fields                                                   |
| ----------------------- | ------------------ | ------------------------------------------------------------ |
| **MediaModel**          | Base file storage  | code, mimeType, size, altText (i18n), folder, catalogVersion |
| **MediaContainerModel** | Format grouping    | code, masterMedia, medias[]                                  |
| **MediaFormatModel**    | Processed versions | code, width, height, format                                  |
| **MediaFolder**         | Organization       | code, path, parent                                           |

### 1.2 Key Hybris Features

1. **Catalog-Aware Storage**: Media linked to product catalog versions
2. **Automatic Format Generation**: Single upload → thumbnail, detail, zoom, mobile
3. **Folder Hierarchy**: `/products/`, `/cms/`, `/marketing/`
4. **CDN Integration**: Immutable URLs, cache-friendly paths
5. **i18n Metadata**: altText, title, description per language
6. **DAM Principles**: Searchable, versioned, organized

### 1.3 Multi-Tenant Pattern

```
File Path: /media/{tenant_id}/{catalog_id}/{folder}/{media_code}.{ext}
Database: No tenant_id column (physical isolation via database-per-tenant)
```

### 1.4 Hybris Storage Strategies

| Strategy                           | Ortam      | Açıklama             |
| ---------------------------------- | ---------- | -------------------- |
| `LocalFileMediaStorageStrategy`    | On-premise | Yerel dosya sistemi  |
| `WindowsAzureBlobStorageStrategy`  | Cloud      | Azure Blob Storage   |
| `S3MediaStorageStrategy`           | Cloud      | Amazon S3            |
| `GoogleMediaStorageStrategy`       | Cloud      | Google Cloud Storage |
| `MongoDBGridFSMediaStorageFactory` | Hybrid     | MongoDB GridFS       |

> **Not**: AdminCraft Phase 1'de `LocalStorageAdapter`, Phase 2'de S3/Azure desteği planlanmıştır.

3. No BaseEntity extension (inconsistent with other modules)
4. No uuid/uid pattern (Component Library uses both)

## 4. Recommended Architecture

### 4.1 Database Schema (Tenant-Specific - Full DAM)

```sql
-- V6__media_baseline.sql

-- ============================================
-- 1. MEDIA FORMAT DEFINITIONS (System + Custom)
-- ============================================
CREATE TABLE media_formats (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    uuid VARCHAR(36) NOT NULL UNIQUE,
    uid VARCHAR(50) NOT NULL UNIQUE,
    code VARCHAR(50) NOT NULL UNIQUE,
    name VARCHAR(100) NOT NULL,
    width INT NOT NULL,
    height INT NOT NULL,
    quality INT DEFAULT 80,
    crop_mode ENUM('FIT', 'FILL', 'COVER') DEFAULT 'FIT',
    is_system BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

    INDEX idx_media_format_code (code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- System format presets (R__seed_media_formats.sql)
-- THUMBNAIL: 100x100, SMALL: 300x300, MEDIUM: 600x600, LARGE: 1200x1200

-- ============================================
-- 2. MEDIA FILES (Master/Original)
-- ============================================
CREATE TABLE media (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    uuid VARCHAR(36) NOT NULL UNIQUE,
    uid VARCHAR(50) NOT NULL UNIQUE,

    -- File Properties
    original_name VARCHAR(255) NOT NULL,
    file_name VARCHAR(255) NOT NULL,
    file_path VARCHAR(500) NOT NULL,
    mime_type VARCHAR(100) NOT NULL,
    file_extension VARCHAR(20),
    file_size BIGINT NOT NULL,

    -- Image/Video Properties
    width INT,
    height INT,
    duration INT,  -- video duration in seconds

    -- Organization (SAP Hybris style)
    folder_id BIGINT,
    tags JSON,

    -- Access Control
    is_public BOOLEAN DEFAULT TRUE,
    uploaded_by BIGINT,

    -- Storage Provider
    storage_provider ENUM('LOCAL', 'S3', 'AZURE', 'CLOUDINARY') DEFAULT 'LOCAL',
    external_url VARCHAR(1000),
    external_id VARCHAR(255),

    -- Metadata (EXIF, etc.)
    metadata JSON,
    usage_count INT DEFAULT 0,

    -- Status
    status ENUM('PROCESSING', 'ACTIVE', 'ARCHIVED', 'FAILED') DEFAULT 'PROCESSING',

    -- Audit
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    created_by BIGINT,
    updated_by BIGINT,
    last_accessed_at TIMESTAMP,

    INDEX idx_media_folder (folder_id),
    INDEX idx_media_mime_type (mime_type),
    INDEX idx_media_status (status),
    INDEX idx_media_is_public (is_public),
    INDEX idx_media_uploaded_by (uploaded_by)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- ============================================
-- 3. MEDIA I18N (Localized Metadata)
-- ============================================
CREATE TABLE media_i18n (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    uuid VARCHAR(36) NOT NULL UNIQUE,
    uid VARCHAR(50) NOT NULL UNIQUE,
    media_id BIGINT NOT NULL,
    language ENUM('TR', 'EN') NOT NULL,

    alt_text VARCHAR(500),
    title VARCHAR(255),
    description TEXT,

    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

    UNIQUE KEY uk_media_i18n_lang (media_id, language),
    FOREIGN KEY (media_id) REFERENCES media(id) ON DELETE CASCADE,
    INDEX idx_media_i18n_media_id (media_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- ============================================
-- 4. MEDIA CONTAINERS (SAP Hybris Pattern)
-- Groups master + generated formats together
-- ============================================
CREATE TABLE media_containers (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    uuid VARCHAR(36) NOT NULL UNIQUE,
    uid VARCHAR(50) NOT NULL UNIQUE,
    code VARCHAR(100) NOT NULL UNIQUE,

    master_media_id BIGINT NOT NULL,  -- Original upload

    -- Audit
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    created_by BIGINT,
    updated_by BIGINT,

    FOREIGN KEY (master_media_id) REFERENCES media(id) ON DELETE CASCADE,
    INDEX idx_container_master (master_media_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- ============================================
-- 5. MEDIA CONTAINER ITEMS (Format Variants)
-- Links container to generated format versions
-- ============================================
CREATE TABLE media_container_items (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    container_id BIGINT NOT NULL,
    format_id BIGINT NOT NULL,
    media_id BIGINT NOT NULL,  -- Generated version

    FOREIGN KEY (container_id) REFERENCES media_containers(id) ON DELETE CASCADE,
    FOREIGN KEY (format_id) REFERENCES media_formats(id) ON DELETE RESTRICT,
    FOREIGN KEY (media_id) REFERENCES media(id) ON DELETE CASCADE,

    UNIQUE KEY uk_container_format (container_id, format_id),
    INDEX idx_container_item_container (container_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- ============================================
-- 6. MEDIA FOLDERS (Hierarchical Organization)
-- ============================================
CREATE TABLE media_folders (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    uuid VARCHAR(36) NOT NULL UNIQUE,
    uid VARCHAR(50) NOT NULL UNIQUE,
    code VARCHAR(100) NOT NULL,
    name VARCHAR(255) NOT NULL,

    parent_id BIGINT,
    path VARCHAR(1000) NOT NULL,  -- Full path: /products/shoes/
    depth INT DEFAULT 0,

    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    created_by BIGINT,
    updated_by BIGINT,

    UNIQUE KEY uk_folder_path (path),
    FOREIGN KEY (parent_id) REFERENCES media_folders(id) ON DELETE CASCADE,
    INDEX idx_folder_parent (parent_id),
    INDEX idx_folder_depth (depth)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- Add FK for media.folder_id
ALTER TABLE media
ADD CONSTRAINT fk_media_folder
FOREIGN KEY (folder_id) REFERENCES media_folders(id) ON DELETE SET NULL;
```

## 5. Completed Backend Implementation (Phases 1-4)

> **Status**: ✅ COMPLETED (As of 2026-01-01)
> **Refactoring**: Includes database, entities, services, controllers, security, and performance optimizations.

### 5.1 Architecture & Database

- **Schema**: Full DAM structure implemented via Flyway (`V20__media_baseline.sql`).
  - Tables: `media`, `media_i18n`, `media_folders`, `media_containers`, `media_formats`, `media_container_items`.
  - **Tenant Isolation**: Physical isolation via database-per-tenant pattern.
- **Entities**:
  - `Media` (BaseEntity): Core file entity.
  - `MediaI18n` (BaseI18nEntity): Localized metadata (altText, title).
  - `MediaFolder`: Hierarchical organization with path management.
  - `MediaContainer`: Groups master file with generated variants (SAP Hybris pattern).

### 5.2 Core Services

- **MediaService**: Transactional CRUD, metadata updates.
- **MediaStorageService**:
  - Async file I/O with `LocalStorageAdapter`.
  - **Security**: Magic bytes validation (prevent malicious uploads), MIME type checks.
  - **Storage Path**: `uploads/{tenantId}/media/{uuid}.ext`.
- **MediaProcessingService**:
  - **Async Processing**: Background format generation using Thumbnailator.
  - **Formats**: Auto-generates THUMBNAIL (100px), SMALL (300px), MEDIUM (600px).
- **MediaFolderService**:
  - Tree management, circular reference detection, safe move operations.

### 5.3 API & Security

- **Controllers**:
  - `MediaController`: Secure (TENANT_ADMIN) CRUD endpoints.
  - `CmsMediaDeliveryController`: **Public** endpoint for CMS, rate-limited (100 req/min/tenant).
- **Observability**:
  - MDC Logging: `tenantId`, `correlationId` added to all logs.
  - OpenAPI: Full Swagger documentation with `@Operation` tags.
- **Performance**:
  - N+1 Prevention: Uses `findByUidIn` for batch retrieval.
  - Pagination: Optimized pageable queries.

## 8. Design Decisions

| Decision          | Choice                  | Rationale                                                               |
| :---------------- | :---------------------- | :---------------------------------------------------------------------- |
| **Entity Design** | **New Pattern**         | `Media` + `MediaI18n` ensures clean separation and multi-lang support.  |
