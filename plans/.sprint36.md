# Media Module Implementation Plan (Sprint 36)

## Executive Summary

Complete implementation of the **Media Module (DAM)** for AdminCraft, adapted from SAP Hybris architecture.
**Backend**: ✅ COMPLETED (Phases 1-4) + Optimization
**Frontend**: ✅ COMPLETED (Phases 5-6) + Optimization + **Media Features**

---

## 1. Backend Implementation (Completed)

> **Status**: ✅ Deployed & Verified (as of 2026-01-03)

### 1.1 Architecture (Database-per-Tenant)

- **Physical Isolation**: No `tenant_id` columns. Separate DB schemes per tenant.
- **Migration**: Flyway `V20__media_baseline.sql` implemented full DAM schema.

### 1.2 Core Entities

| Entity             | Purpose            | Key Features                                                               |
| :----------------- | :----------------- | :------------------------------------------------------------------------- |
| **Media**          | Base file record   | `uuid`, `mimeType`, `storageProvider` (LOCAL), `fileSize`, `focalPointX/Y` |
| **MediaI18n**      | Localized metadata | `altText`, `title`, `description` (per language)                           |
| **MediaContainer** | Variants Grouping  | SAP pattern: Master Media + Generated Formats (Thumb, Small, etc.)         |
| **MediaFormat**    | Format definitions | `width`, `height`, `quality`, `cropMode`                                   |

### 1.3 Key Services

- **MediaStorageService**: Async I/O, `uploads/{subdomain}/media/` path structure, Magic Bytes validation.
- **MediaProcessingService**: Background format generation (Thumbnailator).
- **TenantFilter**: Robust tenant resolution via `X-Tenant-ID`, `X-Forwarded-Host`, `Referer`, or `Origin`.
- **Controllers**:
  - `MediaController`: Secure (TENANT_ADMIN) APIs + **Public** file download (`/api/media/files/**`).
  - `CmsMediaDeliveryController`: **Public** read-only access for CMS, Rate-limited.

### 1.4 API Endpoints (Core)

```http
GET    /api/media                  # List (paginated)
POST   /api/media/upload           # Upload single file
POST   /api/media/composite        # Atomic Upload + Metadata + i18n
GET    /api/media/containers/{id}  # Get variants
POST   /api/media/{id}/generate-format # Generate specific format
PUT    /api/media/{id}/focal-point # Update focal point
GET    /api/cms/media/{uid}        # Public CMS Access
```

## 2. Frontend Implementation (Completed)

> **Status**: ✅ Implemented (Angular 19 + Signals)

### 2.1 Architecture

- **Location**: `storefront/src/app/modules/admin/custom/media/`
- **Pattern**: `CrudHttpService` + `CrudStore` (Signals).
- **State Management**: Fully reactive signals for `items`, `loading`, `filters`.

### 2.2 Implemented Components

#### Core Components

1. **MediaListComponent** (`list/`)

   - Grid view layout with Search and Type Filter.
   - Extends `BaseCrudListComponent<Media>`.

2. **MediaUploadDialogComponent** (`dialogs/media-upload-dialog/`)

   - **Composite Upload**: Sends file + metadata + i18n in one request.
   - Drag & Drop support with progress tracking.

3. **MediaDetailDialogComponent** (`dialogs/media-detail-dialog/`)
   - **Dynamic Tabs**: General, Languages, **Formats**, **Tools**.
   - **Preview**: Displays image/video/audio with `publicUrl`.
   - **Format Generator**: Create custom or preset sizes on the fly.
   - **Focal Point Picker**: Set image focal point for smart cropping.

## 3. Developer Guide

### How to Add a New Format Preset

1. Define the format in the database (`media_formats` table) or use "Custom" mode in UI.
2. In frontend, presets are loaded dynamically if an endpoint is provided, currently we use "Custom" or predefined codes in backend logic.

### How to Use Format Generator

1. Open Media Detail > "Formats" tab.
2. Select **Preset** (if available) or **Custom**.
3. Enter Width/Height (for Custom).
4. Select Output Format (Original, JPEG, PNG, WEBP).
5. Click **Generate**.
6. Outcome: A new variant is created in `media_container_items` and stored physically.

### How to Use Focal Point

1. Open Media Detail > "Tools" tab (Images only).
2. Click on the image to set the point of interest (red marker).
3. Click **Save**.
4. Usage: Coordinates (`focalPointX`, `focalPointY`) are saved (0.0 - 1.0 range) and can be used by frontend/CDN for smart cropping.

## 4. Phase 2 Roadmap (Future Improvements)

The following features are planned for the next iteration to enhance the DAM capabilities:

| Feature                     | Description                                                                                   | Priority |
| :-------------------------- | :-------------------------------------------------------------------------------------------- | :------- |
| **Batch Format Generation** | UI to generate formats for multiple selected images at once. (Backend API exists).            | High     |
| **Auto-Generate Rules**     | Configuration to automatically generate specific formats (e.g., thumbnail, webp) upon upload. | Medium   |
| **Smart Crop API**          | Public endpoint to serve images cropped on-the-fly using the saved Focal Point.               | Medium   |
| **Media Usage Tracking**    | Track where media is used (pages, contents) and prevent deletion if in use.                   | High     |
| **Image Editor**            | Basic cropping/checkers/filters directly in the browser before saving.                        | Low      |
