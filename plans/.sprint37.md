# Sprint 37: Component-Media Integration & Responsive Media

## Executive Summary

Integration of the Component Library with the Media Module, enabling Responsive Media support at both Component and Entry levels. Implementation of `ResponsiveMediaSet` for managing device-specific assets.

**Backend**: ✅ COMPLETED (Phases 1-4)
**Frontend**: ✅ COMPLETED (Phases 5-8)

---

## 1. Backend Implementation (Completed)

> **Status**: ✅ Deployed to Dev Environment

### 1.1 Architecture & Schema

- **ResponsiveMediaSet**: Entity linking `desktop` and `mobile` media assets (`OneToOne` relationships).
- **Component & Entry Association**: Both `Component` and `ComponentEntry` entities have `responsive_id` FK. Deletion automatically cleans up associated links.
- **Entry Field Type**: `MEDIA` field type added to `EntryFieldType` enum, stored as `BIGINT` (referencing `ResponsiveMediaSet` ID).
- **ComponentMediaLink**: Tracks media usage by components/entries, enabling the "Linked Components" feature.

### 1.2 CMS Delivery API (Expanded Responses)

The Delivery API (`/api/cms/*`) has been updated to automatically expand `MEDIA` fields from IDs to rich objects using `MediaFieldExpander` utility with batch fetching (`findByIdIn()`) to prevent N+1 queries.

**Response Structure (Component & Page):**

```json
{
  "uid": "hero-compo",
  "type": "HeroComponent",
  "responsive": {
    "desktop": { "url": "...", "width": 1920 },
    "mobile": { "url": "...", "width": 768 }
  },
  "entries": [
    {
      "responsiveMedia": {
        "desktop": { "url": "...", "width": 1920 },
        "mobile": { "url": "...", "width": 768 }
      },
      "backgroundImage": {
        // Expanded MEDIA field
        "desktop": { "url": "...", "alt": "Bg Desktop" },
        "mobile": { "url": "...", "alt": "Bg Mobile" }
      }
    }
  ]
}
```

### 1.3 Key Services

- **ResponsiveMediaService**: CRUD operations for responsive media sets with `@Transactional` management.
- **MediaFieldExpander**: Shared utility for expanding MEDIA fields in delivery responses (used by both `ComponentDeliveryServiceImpl` and `PageDeliveryServiceImpl`).
- **ResponsiveMediaController**: REST endpoints with `@Positive` validation for media IDs.
- **GlobalExceptionHandler**: Includes dedicated handlers for `MediaNotFoundException`, `InvalidFileException`, `MediaProcessingException`, and `UnsupportedFormatException`.

## 3. Frontend Implementation Guide

### 3.1 Using Responsive Media Picker

Use this component when you need a Desktop/Mobile pair (e.g., for component backgrounds).

```html
<spa-responsive-media-picker [formControl]="mediaControl" label="Background Media"></spa-responsive-media-picker>
```

**Value Format (Input/Output):**

```typescript
interface ResponsiveMediaValue {
  desktop: number; // Media ID
  mobile: number; // Media ID
}
```

### 3.2 Using Single Media Picker

Use this component for selecting a single image/file (e.g., for entry fields).

```html
<spa-media-picker [formControl]="imageControl" label="Select Image"></spa-media-picker>
```

**Value Format:** Returns the `Media ID` (number).

### 3.3 Handling MEDIA Field Type in Entries

When defining a component type via the UI:

1.  Add a new Field.
2.  Select **MEDIA** as the Field Type.
3.  (Optional) Set formatted Key (e.g., `heroImage`).

**Runtime Behavior:**

- The **Entry Form** automatically detects the `MEDIA` type and renders the `SpaMediaPicker`.
- The value saved to the backend is the `ResponsiveMediaSet` ID.
- The **Delivery API** automatically expands this ID into the full Desktop/Mobile object structure.

### 3.4 Linked Components Feature

To view where a media file is being used:

1.  Navigate to **Media Library**.
2.  Click on any media item to open the **Details Dialog**.
3.  Select the **Linked Components** tab.
4.  Click the **Edit** icon on any listed component to navigate directly to its edit screen.
